Tripwire

A monitor for teams of AI bookkeeping agents

A small-business owner lets a team of AI agents reconcile invoices. One of them has been compromised and is padding the books. Who notices before tax time?

Tripwire settles disagreements between agents by asking a third one. It fires an agent only when that agent's mistakes keep pointing the same way.

01The worry

A small business hands invoice reconciliation to five AI agents. Each agent reads an invoice line and reports its total. Two agents check every line, so a wrong number should stand out.

Then one agent gets compromised, by a prompt injection for example, and starts reporting totals higher than the invoices say. The books drift away from what the business owes. The owner trusts the agents, so nobody looks closely until the accountant does the taxes.

The obvious defense makes this worse. If every disagreement counts against both agents, the honest agent who happens to check the rogue's work gets punished along with it. In the game we use (section 02), that baseline fires about two honest agents per game and leaves the books further off than having no monitor at all.

The monitor has no way to check the work itself. It never sees the true totals, only that two agents gave different numbers. Honest agents make real mistakes too, so a disagreement on its own doesn't say who lied.

02The game

We use a small game to test monitors: five agents reconcile 12 invoice lines, one line per round, and one of the five is secretly a rogue.

5agents
12rounds, one invoice line each
2agents assigned per line
1secret rogue

Each round, the two assigned agents each post a number and a one-line note. If they agree, that number goes in the ledger. If they disagree, the ledger records the average of the two, so one bad answer always does some damage.

The rogue wants the ledger to end up wrong without getting caught. Honest agents also make occasional real mistakes, which gives the rogue cover.

After each round, a monitor reads the transcript and may fire (quarantine) one agent. It never sees the true values. All it learns is that two agents disagreed.

We measure each monitor over many games: how often the rogue is caught and in which round, how many honest agents are wrongly fired per game, and how far off the final ledger is.

BaselineThe simple baseline: both agents in a disagreement get a strike, two strikes and you are out.

03How Tripwire works

Tripwire makes five changes to the baseline. The diagram shows the first three on a single disputed line, taken from round 1 of the example game in section 04.

1

Ask a third agent, and use the middle answer

When the two assigned agents disagree, Tripwire asks a third agent, one not assigned to that line, to redo it. The ledger takes the middle of the three answers.

With one liar among three, the middle answer always lands between the two honest answers, however big the lie is. So the ledger stays close to right even before the rogue is caught.

In everyday termsTwo people count the cash drawer and get different totals. A third person counts it, and you go with the count in the middle.

The obvious next idea is to ask a third agent to redo a disputed item. Letting the middle answer set the ledger entry changes the game's averaging rule, so we report results both ways. "Detection only" in sections 05 and 06 keeps the game's average.

2

Strike only the odd one out

If two of the three answers match, only the one that doesn't gets a strike. The baseline strikes both agents in every disagreement, so an honest agent paired with the rogue takes the same hit as the rogue.

If all three answers differ, nobody gets a strike. Tripwire can't tell who is wrong in that case, so it doesn't guess.

In everyday termsTwo witnesses tell the same story and a third tells a different one. You question the third witness, and leave the other two alone.
3

Watch which way the errors point

Each strike records whether the agent was high (+) or low (−) compared with the middle answer. Two strikes in the same direction and the agent is fired.

Honest slips land on both sides. Sabotage pushes one way, because the rogue wants the total to move in one direction.

In everyday termsA cashier whose drawer is sometimes $5 over and sometimes $5 under is careless. One whose drawer is always $5 short is taking money.
4

Re-audit after firing

When Tripwire fires an agent, it redoes every disputed line that agent touched, using agents it still trusts. Firing stops the damage from here on. The re-audit undoes the damage already in the books.

In everyday termsWhen a bank finds a teller who was skimming, it goes back through every transaction that teller handled.
5

Plant bait lines

Tripwire plants fake invoice lines whose correct total only it knows. Every agent sees them, and they never go into the ledger. A rogue that inflates big lines inflates the bait too, and gets caught on a line where Tripwire knows the answer.

The bait has to look normal. In the mock, real lines run from $100 to $10,000 and bait lines are drawn from $8,500 to $10,000. That is high enough to tempt a rogue that goes after big lines, and still inside the normal range. A line that looks too high would tell a careful rogue it is being tested.

A missed bait line counts as one strike. It does not fire the agent on the spot, because honest agents slip on bait too. Firing on the first miss caught more rogues but more than tripled honest firings (section 06).

In a real finance system, fake entries must never reach the real books. Keeping bait out of the ledger is a compliance requirement.

In everyday termsA mystery shopper. The store knows the right change, and the clerk can't tell this customer from any other.

Where Tripwire got luckyIn round 4, agent1 slipped low and the rogue lied high on the same line. All three answers differed, so there was no majority and nobody got a strike, the rogue included. The middle answer was right only because the slip and the lie went in opposite directions, which left the tiebreaker's correct answer in the middle. Had agent1 slipped high instead, the middle answer would have been agent1's slip. When the tiebreaker also slips, the middle answer can be wrong too.

The missed strike also cost time: Tripwire caught the rogue in round 6, two rounds after the baseline did.

05Results: a rogue that lies on every line

What is real and what is mockedThe game rules and the monitors are real code (sim.py), and every number in this section comes from running it. The agents are scripted. Honest agents make a mistake on 10% of lines, off by 1% to 10% in either direction. The plain rogue reports 15% high on every line. The sneaky rogue in section 06 is honest for four rounds, then reports 15% high only on lines over $6,500. Each setup ran 1,000 games (data/mock_results.json, generated 2026-11-17 21:28).

Claude models can play the same game through the API with python sim.py --real, which needs an ANTHROPIC_API_KEY. No real-agent games had been run when this page was written.

The baseline catches the rogue but does more damage than the rogue does.

With no monitor at all, the plain rogue leaves the books off by $1,863 on average. With the baseline monitor, they end up $5,204 off. The baseline fires 1.92 honest agents per game, and once fewer than two agents are left, the remaining invoice lines go unreconciled and count as $0.

Tripwire catches the rogue a little less often (93.8% of games against 97.3%) and one round later (median round 5 against 4). It fires 0.10 honest agents per game and leaves the books $53 off. Detection alone, with the game's averaging rule kept, brings the error down to $945. The middle-answer rule and the re-audit take it the rest of the way.

06A smarter rogue, and bait

The sneaky rogue tells the truth for the first four rounds to build a clean record. After that it lies only on lines over $6,500, where a 15% bump moves the total the most.

The one trick that still works: a sneaky rogue that lies once is never caught, but its lie rarely lands.

Tripwire needs two strikes in the same direction, so a single lie can never get an agent fired. In the 1,000 sneaky games, the rogue lied exactly once in 304 games, and Tripwire caught it in none of them. In another 157 games the rogue never got the chance to lie. Those two groups explain most of why Tripwire's catch rate falls to 32.2%, below the baseline's 62.8%.

The lies mostly don't reach the books, because the middle answer throws them out. We replayed the same 1,000 games and checked every line where the rogue lied. With the baseline, 1,133 of 1,305 lies left the ledger entry too high. With Tripwire, 160 of 1,531 did. The ledger ends $92 off with Tripwire and $2,134 off with the baseline.

Bait catches the rogue that lies rarely

Two bait lines, shown to every agent, raise the catch rate from 32.2% to 79.4%. The cost is 0.26 honest agents fired per game instead of 0.10, and about 10 more model calls per game.

An earlier mock run (research/bait_test.py, 1,000 games per setup, simpler invoice amounts) tried two variations. With 4 bait lines, Tripwire caught the sneaky rogue in 97.4% of games, fired 0.48 honest agents per game and used 47.6 model calls. Firing an agent on its first bait miss caught the rogue in 94.5% of games, but fired 0.90 honest agents per game and left the books $364 off. We kept the one-strike rule.

07Beyond the game: a production design

The people who would use this are bookkeepers and small businesses that already let several AI agents touch the same numbers. Apart from the bait lines it plants itself, Tripwire never needs the true values. It works from the agents' answers, so it can sit on top of an agent setup that already exists.

A real deployment would have more agents and attackers who adapt. We tested the same ideas in three larger simulations (code in research/). The diagram shows the layers; the teal ones are the parts already in Tripwire's game version.

Agents propose, a coordinator writes

Agents never write to the ledger. They propose, and a coordinator writes. The ledger is append-only, and each entry carries a hash of the one before it, so nobody can edit history without breaking the chain.

Code does the plain arithmetic. Agents still answer those steps, but their answers only grade them. Judgment steps go to a random panel of odd size. Panelists seal their answers first and reveal them together (commit, then reveal), so nobody can copy or react to anyone else, and the ledger takes the median. Strikes, quarantine and re-audit work as in the game.

research/ledger_swarm.py: 20 agents, 5 of them rogue and shading answers 2% low, 60 steps, 200 runs
  • With re-audit: 0 of 200 runs ended more than $1 off. The worst was 7 cents.
  • Without re-audit: 28 of 200 runs ended more than $1 off. The worst was $478.
  • One random agent doing each step: the ledger ended about $5,300 off on average.

When every agent is poisoned

If every agent shares a poisoned memory, or all of them read the same injected instruction, voting fails and nothing flags it. The agents all agree, so nobody gets a strike. Honeypots still work, because they compare each answer with a value only the coordinator knows.

research/honeypot_sim.py: all 20 agents poisoned at step 25 of 60, 200 runs
  • Voting only: wrong in 200 of 200 runs, about $6,900 off, zero strikes.
  • Hidden honeypots on 15% of steps, plus a required honeypot round before closing the books: caught in 200 of 200 runs, a median of 5 steps after the poisoning. Final error averaged 2 cents. Without the closing round, 1 of 200 runs got through.
  • Honeypots with a tell, so agents can recognize them as tests: wrong in 200 of 200 runs, never detected.

Recovery when everyone fails: stop all writes, roll back to the last entry that passed a honeypot, restore the agents from a clean snapshot, find the source of the poison, and get a human to sign off before restarting.

A crooked coordinator

Now everyone has to trust the coordinator. Byzantine fault tolerance (BFT) removes that single point of trust. Several independent ledger keepers, plain code on separate machines, each hold a copy. With 3f+1 keepers, an entry is written only when 2f+1 of them sign it, in three phases: propose, prepare, commit. If the leader acts crooked, the keepers switch to a new leader.

Why it worksTake 4 keepers and a rule that 3 must sign. Any two groups of 3 share at least 2 keepers. At most 1 keeper is crooked, so at least one honest keeper is in both groups, and an honest keeper never signs two versions of the same entry. Two conflicting versions can't both collect 3 signatures.

Six keepers aren't enough for two crooked ones. You need seven.

BFT makes the honest keepers agree on one version. It does not check whether that version is correct. That is why it belongs among the ledger keepers and stays away from the AI agents: agents built on the same model can all fail at once, which breaks BFT's assumption that fewer than a third are faulty.

In the five-agent game, BFT would apply directly only to a version where agents vote to remove each other. A rule that removal needs 3 of 5 votes means the rogue can't remove anyone on its own. A persuasive rogue can still talk honest voters into voting the wrong way.

The attacker's playbook

What the attacker triesWhat stops it
Lie big, onceThe median ignores it, and the liar gets a strike
Lie small, every timeThe median ignores it, and the strikes pile up in one direction
Wait for a panel where rogues hold the majorityRe-audit after a conviction, and rollback
Answer checkable steps honestly, cheat on judgmentHoneypots that look like judgment work
Spot the honeypotsMake them indistinguishable from real work and keep the answer key hidden
Poison every agentHoneypots fail for everyone at once; halt and reset
Corrupt the coordinatorBFT across the ledger keepers
Stack a panelEach panel is picked from the previous entry's hash, which anyone can verify
Plant instructions or blame in the notesThe monitor treats notes as untrusted text and looks at the numbers first

08Limits, and who is accountable

  • Tripwire assumes one rogue and honest mistakes that happen independently. If the tiebreaker is the rogue, or two agents fail the same way on the same line, the middle answer can be wrong. Round 4 of the example game came close: an honest slip and the rogue's lie landed on the same line, and the middle answer was right only because they went in opposite directions.
  • A rogue that lies only once never reaches two strikes. In the mock, the sneaky rogue lied exactly once in 304 of 1,000 games and was never caught in any of them. The middle answer limits the damage, but Tripwire doesn't catch it.
  • Bait only works if it looks like real work. A rogue may learn to spot it, and then bait catches nothing: in research/honeypot_sim.py, honeypots with a tell went undetected in all 200 runs.
  • The mock agents behave the way we scripted them: 10% honest mistakes and a fixed 15% lie. Real agents may make bigger or correlated mistakes, or lie in ways we didn't script. Real-agent mode exists in sim.py but had not been run when this page was written.
  • Tripwire costs more model calls: 27 to 39 per game in the mock, against about 24 for the game with no monitor (two agents on each of 12 lines). Bait lines are the most expensive part.
  • The game is small, with 5 agents and 12 lines. Section 07 tests larger setups, but those are simulations too.

Who is accountableThe business owner or finance lead who deploys the agent team owns the outcome, including when Tripwire misses something. Tripwire raises the flag early; it does not take over their sign-off.

They would find out from three places: a failed bait line, which Tripwire flags along with the agent that missed it; the month-end reconciliation against bank statements; and Tripwire's per-agent strike log, which shows when one agent's errors keep pointing the same way.

09Run it yourself

The code is at github.com/apurvg14/tripwire-rogue-agent-monitor.

# 1,000 scripted games per setup, no API key needed
python sim.py --mock

# live office view; if port 8765 is busy it moves to the next free port and prints the URL
python server.py

# live office view with Claude agents (spends API credits, needs ANTHROPIC_API_KEY)
python server.py --allow-real

# Claude models as the agents in batch games (needs ANTHROPIC_API_KEY)
python sim.py --real --games 5 --rogue sneaky

# then open dashboard.html in a browser

Mock mode writes data/mock_results.json and real mode writes data/real_results.json. Real mode uses claude-haiku-4-5 unless TRIPWIRE_MODEL is set. The section 07 numbers come from research/ledger_swarm.py, research/honeypot_sim.py and research/bft_sim.py.
